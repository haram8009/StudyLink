# 3일차 프런트 구현 기록 — 퀴즈·오답노트·노트 초안·관련 노트

2026-10-22. [3일차 PRD](studylink-day3-prd.md)의 "화면" 절과 HTTP 계약, 사용자 스토리 1~41을 기준으로 A 담당 화면을 구현했다. 2일차 채팅·공통 자원 패널 구조([day2-frontend](day2-frontend.md))는 그대로 두었다.

## 화면 구성

- **워크스페이스 메뉴**: 워크스페이스 제목 아래 `채팅 / 퀴즈 / 오답노트` 탭(`WorkspaceNav`). 퀴즈·오답은 워크스페이스 단위라서 어느 채팅에서 들어가도 같은 화면이다.
- **퀴즈** `/w/:id/quiz`, `/w/:id/quiz/:quizId` (한 라우트, 선택적 세그먼트)
  - 왼쪽: "새 퀴즈 만들기"(5문항 요청)와 최근 퀴즈 목록(점수 또는 "풀이 중", 부분 생성이면 "5문항 중 N문항"). 처리 완료 자료가 없으면 버튼 비활성과 업로드 안내.
  - 생성 중: 버튼 비활성, "문항 만드는 중…"과 경과 초 표시(30초 안팎, 최대 45초 안내). 퀴즈를 바꿔 봐도 같은 페이지 컴포넌트라 진행 상태가 유지된다.
  - 가운데 풀이: 문항·4지선다·근거 자료명·페이지 칩. 선택은 바꿀 수 있고 `localStorage['studylink-quiz-answers-{quiz_id}']`(try/catch)에 보관해 새로고침 후에도 남는다. 제출 버튼 → 미응답이 있으면 해당 문항 강조·번호 안내(전 문항 응답이 계약 조건) → 모두 답했으면 "제출하면 답을 바꿀 수 없어요" 확인 후 제출.
  - 부분 생성(`actual_count < requested_count`)이면 "N문항만 만들었습니다" 안내.
  - 채점 후: 점수 카드, 문항별 정답/오답, 내 답·정답 표시, 해설, 발췌. 틀린 문항이 있으면 오답노트 링크.
  - 새로고침·재방문 시 항상 `GET /api/quizzes/{id}`로 복구한다(생성 응답은 즉시 표시용으로만 쓴다).
- **오답노트** `/w/:id/reviews?status=reviewed&review=<id>`
  - 왼쪽: 복습 전/복습함 필터(쿼리 `status`), 오답 목록(문제·자료·페이지·메모 여부).
  - 가운데: 문제·내 답·정답·해설·발췌, 근거 페이지 칩, 관련 노트(최대 3개, "이 워크스페이스에 연결됨"/"연결 안 됨" 표시, 누르면 노트 미리보기), 관련 노트가 없으면 "관련 노트 없음"과 노트 작성 안내, `related_notes_status: "unavailable"`이면 "지금 불러올 수 없어요"와 다시 불러오기. 틀린 이유 메모(2,000자, 글자 수 표시), "복습함으로 표시"/"복습 전으로 되돌리기". 상태가 바뀐 오답은 현재 필터 목록에서 빠지고 상세는 열린 채로 둔다.
- **근거 열람 패널**(퀴즈·오답 화면 오른쪽): 2일차 `DocViewer`·`NotePreview`를 그대로 재사용한다. PDF는 `document_id-page-요청시각` key로 다시 마운트한다. 자료가 워크스페이스에 없거나 ready가 아니면 칩이 "원문을 열 수 없음"으로 바뀌어 비활성화되고, 뷰어도 같은 안내를 보인다(이 처리는 채팅 인용에도 적용된다).
- **노트로 만들기**(채팅 답변마다): 근거 부족 답변은 비활성과 안내. 누르면 `POST /answers/{id}/note-draft` → 공통 자원 패널의 `연결 노트` 탭에 "답변에서 만든 노트 초안" 편집기(기존 `NoteEditor`)를 채운다. 초안 인용 `[cN]` 칩(본문에서 지운 인용은 취소선), fallback이면 "요약 없이 답변을 옮겨 담음" 경고, "이 워크스페이스에 연결"(기본 체크) 후 저장하면 노트 미리보기가 열린다. 저장 때 `citations`는 서버 초안 형식 그대로 보낸다.
- **관련 노트 찾기**(`NoteEditor` 안의 버튼): 새 노트 작성, 노트 초안, 노트 수정에서 저장 전 제목·본문으로 `POST /notes/related`(수정 중이면 `exclude_note_id`)를 호출해 최대 3개를 보여준다. 새 노트·초안에서는 "열기"로 미리보기를 연다. 노트 미리보기 안에서 수정 중일 때는 다른 노트를 열면 편집 내용이 사라지므로 제목·발췌만 보여주고 열기 버튼은 두지 않았다.
- 좁은 화면: 1350px 이하에서 목록·본문 2열 + 열람 패널 아래 전체 폭, 850px 이하에서 목록 → 본문 → 열람 순서의 한 열.

파일: `frontend/src/Study.jsx`(퀴즈·오답 화면, 새 파일), `frontend/src/study.css`(새 파일), `frontend/src/Workspace.jsx`(메뉴, 노트로 만들기, 초안 편집, 관련 노트 버튼, `DocViewer`·`NotePreview`·`NoteEditor` export, 원문을 열 수 없음), `frontend/src/api.js`(클라이언트·목), `frontend/src/ui.jsx`(`WorkspaceNav`, `shortTime`), `frontend/src/main.jsx`(라우트).

## 사용 API

`POST/GET /api/workspaces/{id}/quizzes`, `GET /api/quizzes/{id}`, `POST /api/quizzes/{id}/submit`, `GET /api/reviews?workspace_id=&status=`, `GET/PATCH /api/reviews/{id}`, `POST /api/answers/{id}/note-draft`, `POST /api/notes/related`, 그리고 2일차의 `GET /api/workspaces/{id}`·노트 API.

- 오류는 문자열 `detail`을 우선 표시한다. detail이 문자열이 아닐 때만 화면별 기본 문구를 쓴다: 퀴즈 생성 400(출제할 자료 없음)·409(생성 중)·422(문항 0개)·503, 제출 422, 초안 422·503.
- 채점 여부는 `submitted_at`이 있고 문항에 `answer_option_id`가 있는지로 판단한다.

## 목 모드

`cd frontend && VITE_USE_MOCK=true npm run dev`. 데이터는 브라우저 localStorage(`studylink-preview-v1-quizzes`, `-reviews` 등)에만 둔다.

- 퀴즈 생성: 처리 완료 자료의 페이지를 돌아가며 내장 문항 5개(잔차 연결·기울기 소실·어텐션 스케일링·BPE·임베딩)를 내고 선택지를 섞는다. 약 2.2초 걸리며 같은 워크스페이스 생성 중 재요청은 409, ready 자료가 없으면 400이다.
- 퀴즈 화면 왼쪽의 **목 시나리오** 선택(목 모드에서만 보임): 정상 5문항 / 부분 생성(3문항) / 0문항(422) / 공급자 장애(503) / 근거 자료 없음 1문항(첫 문항의 자료를 없는 ID로 바꿔 "원문을 열 수 없음" 확인용).
- 제출: 전 문항·해당 퀴즈 선택지가 아니면 422이고 저장하지 않는다. 첫 제출만 채점·오답 생성, 재제출은 저장된 결과를 그대로 돌려준다.
- 오답 단건의 관련 노트, `/notes/related`: 색인 성공 노트 중 단어가 많이 겹치는 순으로 최대 3개, linked는 워크스페이스 연결 여부.
- 노트 초안: 원 답변 segments가 쓴 인용만 `[eN]`→`[cN]`으로 옮긴다. 질문에 "요약 실패"가 들어간 답변은 `fallback: true`, 근거 부족 답변은 422.
- 노트 저장 목이 이제 실제 백엔드와 같은 인용 형식 `{id:'cN', source_type, document_id, page, quote, note_id}`를 받는다(2일차 목의 `citation_id`도 읽는다).
- 수동 검증용으로 목 모드에서만 `window.studylinkMock`에 목 API를 노출한다(재제출·409처럼 화면에서 직접 만들 수 없는 요청 확인용).

## 계약 가정

- 제출 응답과 제출 후 `GET /quizzes/{id}`는 같은 형식이다. 백엔드 `QuizGraded`가 `workspace_id`·`requested_count`·`actual_count`·`created_at`도 주지만 화면은 없어도 동작한다.
- `GET /reviews/{id}`의 `related_notes_status`(`ok`|`unavailable`)는 PRD에 없는 백엔드 추가 필드로 보고 선택적으로 처리했다.
- PATCH 응답에는 related_notes가 없으므로 화면에 있던 관련 노트를 유지한다.
- 노트 초안 `citations`는 노트 저장 입력 형식(`id`, `source_type`, `document_id`, `page`, `quote`, `note_id`)이라고 보고 그대로 저장 요청에 넣는다. 인용 칩의 자료명은 표시하지 않고 페이지만 보여준다.
- 퀴즈 생성 요청 count는 항상 5다(PRD 범위 밖: 문항 수 사용자 지정).
