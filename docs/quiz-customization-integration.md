# 퀴즈 설정 변경 통합 기록

작성일: 2026-10-22 (Asia/Seoul)
기준: [퀴즈 변경 PRD](quiz-customization-prd.md).

## 병렬 작업 경계

- 프런트 에이전트: `frontend/`의 설정 화면, API 호출, 브라우저 목 모드, 참고 자료 표시와 프록시.
- 백엔드 에이전트: `backend/`의 입력·응답 스키마, 이전 DB 이관, 생성·보충 그래프, 저장·채점, 자동 테스트.
- 통합 담당: 공통 API 계약, `docs/` 갱신, 변경 검토와 최종 검증. 담당 밖 파일 변경은 먼저 조율한다.

실제 제품 저장소는 `D:/SSAFY/studylink`다. 요청의 날짜형 PRD 파일명은 발견되지 않았고, 동일 요구를 담은 기존 `docs/quiz-customization-prd.md`를 읽어 작업했다. 기존 PRD 파일명은 유지한다. 작업 시작 시 이미 수정된 UI·문서·AGENTS.md와 미추적 파일을 보존한다. 같은 작업 디렉터리를 사용하되 파일 소유 범위를 분리하며 커밋·reset·운영 DB 변경을 수행하지 않는다.

## 공통 계약

- 생성 요청: `count`는 엄격한 정수 1~10(기본 5), `difficulty`는 `easy|medium|hard`(기본 `medium`). 신규 성공은 정확히 요청 수만 저장한다.
- 생성·조회·제출·목록 응답에 난이도를 포함한다. 과거 난이도는 `null`로 유지하고 화면에서는 미지정으로 표시한다. 과거 부분 퀴즈의 개수와 점수는 보존한다.
- 실패: 근거 없음 400, 같은 워크스페이스 생성 중 409, 검증·중복 보충 소진 422, 시간 초과·전체 공급자 장애 503. 실패한 임시 문항은 저장하지 않는다.
- 생성 예산: 최초 포함 5라운드, 슬롯당 라운드별 최대 2회, 전체 120초, 동시 호출 최대 5개. 기존 통신 재시도는 어댑터가 관리한다.
- 제출 전 정답·해설·인용문은 노출하지 않는다. 제출 후 기존 `document_id`, `filename`, `page`, `quote`를 참고 자료 표시와 원문 이동에 재사용한다.

최종 `git diff --check`에서 공백 오류는 없었다(CRLF 변환 안내만 표시). 프런트·백엔드가 담당 파일 밖을 수정하지 않았는지 변경 목록을 확인했으며, 공통 기획서·아키텍처의 API·데이터 모델·예산을 함께 갱신했다. 기존 UI 수정은 유지했다. Notion 수정·커밋은 수행하지 않았다.

실제 모델 검증은 운영 SQLite를 읽기 전용으로 열어 별도 임시 경로에 backup한 DB에서 FastAPI TestClient로 실행했다. 운영 DB와 실행 중 서버는 변경하지 않았다. 지연은 해당 호출 한 번의 관측치이며 최대 지연 보장이나 모든 난이도·자료의 품질 검증 결과가 아니다. 임시 검증 결과 파일은 저장소에 포함하지 않았다.

## 실제 출력 검토와 후속 작업

- 백엔드 목 모드에서도 문항 번호만 바꿔 중복을 우회하지 않는다. 동일 근거에서 동일 문항만 반환하는 대역은 보충 예산 소진 422로 끝나며 저장하지 않는다. 브라우저 목 모드는 서로 다른 문항 10개의 예시 집합을 사용한다.
- 초기 출력에서 해설이 선택지 문자(`c가 정답`)를 참조했다. 서버의 선택지 섞기와 충돌할 수 있어 정답 내용으로 설명하고 위치·문자를 지칭하지 않도록 프롬프트와 목 해설을 보정했다. `evidence` 등 내부 용어 노출도 금지했다. 보정 후 실제 5문항 표본에서 해당 표현은 보이지 않았다.
- 어려움 설정에서도 단순 역할·정의 질문이 나와 구체적인 조건·변화 상황과 적용·판단을 요구하도록 보강했다. 이후 표본에도 회상형에 가까운 문항이 일부 남는다. 난이도 전달·형식·개수 검증과 교육적 난이도 적합성은 구분한다.
- PRD의 두 데모 자료별 난이도 5문항씩 사람 검토는 수행하지 않았다. 정답 유일성·근거 일치·난이도 적합성 판정이 필요하다. 정규화 중복 검사는 의미가 비슷한 모든 질문을 제거하지 않는다.
- 원격 Langfuse trace 조회·호출 수·보충 횟수의 실측 검토는 미완료다. 실제 API smoke에서는 원격 계측을 꺼 데이터와 네트워크 의존성을 분리했다. 코드의 라운드·종료 사유 계측과 원격 화면 확인을 혼동하지 않는다.

프런트 검증용 Vite 세션은 종료했다. 이번 작업은 기존 UI 개편을 보존하며 설정·참고 자료에 필요한 CSS만 추가했고, 개발 프록시 한도를 150초로 설정했다. 백엔드의 새 코드로 시작할 때 `init_db`가 `quizzes.difficulty`를 자동 추가한다. 기존 행은 `NULL`이며 과거 문항·점수는 갱신하지 않는다.
