# StudyLink PRD — 워크스페이스 개요·채팅 화면 분리와 PDF 추가 업로드

작성일: 2026-10-22 (Asia/Seoul)  
상태: 초안. 요구사항·인수 기준을 작성했으며 구현·실행 검증 전이다.  
기준: [용어집](../CONTEXT.md), [구현기획서 v1.1](studylink-implementation-plan-v1.1.md), [아키텍처](studylink-architecture.md), [ADR 0002](adr/0002-workspace-chats-shared-resources.md).

## 1. 문제와 목표

사용자 요청은 두 가지다. 워크스페이스 전체를 보는 페이지와 개별 채팅에 들어간 페이지를 분리하고, 기존 워크스페이스에 PDF를 추가 업로드할 수 있게 한다.

현재 `/w/:id`는 채팅 목록·선택한 대화·공통 자원을 함께 보여주고 마지막 채팅을 자동 선택한다. 워크스페이스를 둘러보는 행동과 대화하는 행동이 한 화면에 섞여 있다. PDF 추가 업로드는 코드상 `Workspace.jsx`의 `DocsTab`과 `api.upload`에 존재하지만 채팅 화면의 자료 탭 안에 있어 사용자가 찾기 어렵다. 실행 중인 화면에서 업로드가 누락된 별도 원인이 있는지는 아직 검증하지 않았다. 따라서 업로드 백엔드가 없다고 전제하지 않고, 개요에 명확한 추가 진입점을 제공하고 실제 연결을 검증한다.

이 문서에서 ‘워크스페이스 전체’는 **선택한 워크스페이스의 개요**를 뜻한다. 여러 워크스페이스의 목록인 홈(`/`)과 구분한다. 기존 설계에 있던 개요·채팅 경로 분리를 실제 화면 요구사항으로 구체화한다.

## 2. 사용자 흐름

1. 홈에서 워크스페이스를 선택하면 해당 워크스페이스의 개요로 이동한다.
2. 개요에서 제목·학습 목표, 자료, 연결 노트, 채팅 목록을 확인한다.
3. `PDF 추가`로 기존 자료를 유지하면서 새 PDF를 올린다. 처리 상태와 결과는 자료 목록에서 확인한다.
4. 기존 채팅을 선택하거나 `새 채팅`을 누르면 개별 채팅 페이지로 이동한다.
5. 채팅에서는 질문·답변과 인용 근거 확인에 집중하고, `워크스페이스 개요`로 돌아갈 수 있다.
6. 추가 자료가 처리 완료되면 같은 워크스페이스의 기존·새 채팅에서 이후 질문의 검색 대상이 된다.

## 3. 화면과 범위

| 경로 | 책임 | 필수 표시·행동 |
| --- | --- | --- |
| `/` | 모든 워크스페이스 목록 | 기존 목록·생성 유지, 선택 시 개요로 이동 |
| `/w/:id` | 워크스페이스 개요 | 제목·목표, 자료 목록·PDF 추가, 연결 노트 목록·기존 연결 기능, 채팅 목록·새 채팅, 퀴즈·오답노트 이동 |
| `/w/:id/chats/:chatId` | 개별 채팅 | 선택 채팅 제목·대화·질문 입력, 검색 범위 표시, 자료·노트 열람, 인용 열기, 노트 초안 만들기, 개요 복귀 |

개요에는 대화 본문이나 질문 입력창을 표시하지 않는다. 마지막 채팅이 있어도 자동 진입하지 않는다. 개별 채팅에는 워크스페이스 전체 관리 화면을 반복 배치하지 않는다. 자료·노트 열람과 답변에서 노트 만들기는 유지하며, 자료 추가의 기본 위치는 개요다. 채팅의 자료 패널에는 개요의 자료 영역으로 가는 `PDF 추가` 링크를 제공한다.

워크스페이스 내 메뉴의 `/w/:id` 이름은 `개요`로 바꾸고, 개별 채팅에서도 소속 워크스페이스와 현재 채팅이 구분되게 표시한다. 퀴즈·오답노트는 기존처럼 워크스페이스 단위로 유지한다. 작은 화면에서도 개요의 `PDF 추가`, 채팅 진입, 개요 복귀를 찾고 조작할 수 있어야 한다.

### PDF 추가 업로드

- 개요의 자료 영역에 `PDF 추가` 버튼을 항상 표시한다. 자료가 이미 있어도 버튼이 사라지지 않는다. 자료가 없으면 같은 동작의 빈 상태 안내를 제공한다.
- 파일 선택과 자료 영역에 끌어 놓기를 지원한다. 이번 범위는 한 번에 PDF 하나이며 연속해서 추가할 수 있다. 복수 파일을 놓으면 한 개씩 추가하도록 안내하고 임의의 첫 파일만 조용히 올리지 않는다.
- 업로드 중에는 진행 상태를 표시하고 같은 화면의 중복 제출을 막는다. 전송 완료와 분석 완료를 구분한다. 실제 바이트 진행률을 제공하지 않으면 임의의 퍼센트를 표시하지 않는다.
- 업로드 응답을 받으면 새 자료를 목록에 추가한다. `processing`은 분석 중, `ready`는 질문 가능, `failed`는 실패 사유·재시도로 표시한다. 처리 중 문서만 기존 2초 간격으로 상태를 확인한다.
- 비 PDF·유효하지 않은 PDF(422), 크기 초과(413), 통신 실패를 업로드 영역에 표시한다. 재선택·재시도가 가능하고 기존 자료·채팅은 유지한다. 크기 제한은 서버 설정을 기준으로 하며 고정 문구와 불일치하지 않게 한다.
- 스캔 PDF·텍스트 추출 실패는 기존 수집 정책에 따른 실패 상태로 안내한다. OCR은 추가하지 않는다.
- 업로드 실패 후 같은 파일을 다시 선택할 수 있게 입력을 초기화한다. 처리 실패 문서의 재시도는 기존 문서 ID로 수행한다.
- 같은 이름의 PDF가 추가돼도 기존 문서를 덮어쓰지 않는다. 콘텐츠 중복 탐지·자동 병합은 이번 범위에 포함하지 않는다.
- 처리 중·실패 문서는 검색에서 제외한다. 기존 질문 가능 자료나 연결 노트가 있으면 새 자료 분석 중에도 질문할 수 있다. 이미 저장된 답변·인용을 새 자료로 다시 생성하지 않는다.

## 4. 이동과 상태 복원

- 채팅 선택은 URL을 변경한다. 주소 직접 진입·새로고침으로 같은 채팅과 저장된 대화 기록을 복원한다. 브라우저 뒤로·앞으로도 해당 화면을 복원한다.
- 채팅 조회 결과의 `workspace_id`가 URL의 워크스페이스와 다르면 대화 내용을 표시하지 않고 잘못된 경로를 안내한다. 없는 워크스페이스·채팅도 명시적으로 안내한다.
- 새 채팅은 생성 요청이 성공했을 때만 해당 채팅 URL로 이동한다. 실패하면 개요를 유지하고 재시도한다. 생성 중에는 중복 클릭을 막는다.
- 개요로 돌아갔다가 재진입하거나 다른 채팅으로 이동해도 채팅별 대화 기록과 입력 초안이 섞이지 않는다. 저장하지 않은 질문·노트 초안은 같은 탭 안의 화면 이동에서 보존한다. 새로고침 이후 미저장 초안 복원은 이번 범위에서 보장하지 않는다.
- 답변 생성 중 화면을 이동해도 요청을 중복 전송하지 않는다. 복귀하면 진행 상태 또는 완료된 저장 기록을 확인할 수 있어야 한다. 응답이 다른 채팅에 표시돼서는 안 된다.
- PDF 분석 중 페이지를 나가도 서버 수집을 계속한다. 재진입하면 서버에서 상태를 다시 읽어 필요한 폴링을 재개한다. 개요에서 올린 자료가 채팅 진입 때 반영되도록 목록을 갱신한다.
- PDF 업로드 전송 중에는 현재 화면의 작업 상태를 유지한다. 경로 전환으로 전송 상태가 사라지지 않게 하고, 실패한 요청을 성공으로 표시하지 않는다.

## 5. 구현 경계와 기존 계약

자료·연결 노트는 워크스페이스가 공유하고 대화 문맥은 채팅별로 격리한다는 ADR 0002를 유지한다. 채팅별 자료 복사·첨부 테이블, 새 검색 범위, DB 마이그레이션은 계획하지 않는다.

| 영역 | 변경 책임 |
| --- | --- |
| 라우팅·페이지 | 개요·채팅 경로 등록, 홈·메뉴·복귀 링크 연결, 직접 진입과 잘못된 소속 처리 |
| 자료 관리 | 기존 업로더·문서 목록·실패 재시도 재사용, 개요에서 찾기 쉽게 배치, 재진입 상태 동기화 |
| 채팅·공통 열람 | 대화·질문·인용·노트 초안 기능 보존, 경로 전환에도 요청·입력 상태 보존 |

프런트 API 호출은 기존 `src/api.js`에 유지한다. 다음 계약을 재사용하며, 실제 계약 부족이 발견되면 구현 전에 관련 기획서·아키텍처에 함께 기록한다.

| 용도 | 기존 API |
| --- | --- |
| 개요 | `GET /api/workspaces/{id}` |
| 채팅 목록·생성 | `GET/POST /api/workspaces/{id}/chats` |
| 채팅 소속·대화·질문 | `GET /api/chats/{chatId}`, `GET /api/chats/{chatId}/messages`, `POST /api/chats/{chatId}/ask` |
| PDF 추가 | `POST /api/workspaces/{id}/documents` (`multipart/form-data`, `file`) |
| 처리 상태·재시도 | `GET /api/documents/{id}`, `POST /api/documents/{id}/retry` |

## 6. 인수 기준

| ID | 시나리오 | 통과 조건 |
| --- | --- | --- |
| A01 | 홈에서 기존 워크스페이스 선택 | 개요 URL이 열리고 자동 채팅 진입·질문 입력창이 없다 |
| A02 | 개요 확인 | 자료·연결 노트·채팅 목록과 `PDF 추가`·`새 채팅`을 확인할 수 있다 |
| A03 | 기존·새 채팅 열기 | 각 채팅 URL로 이동하고 해당 기록만 표시한다. 생성 실패 시 개요에 오류를 표시한다 |
| A04 | 직접 진입·새로고침·뒤로·앞으로 | URL과 선택 채팅이 일치하고 저장된 기록을 복원한다 |
| A05 | 다른 워크스페이스의 채팅 ID 사용 | 소속 불일치를 안내하고 그 채팅 내용을 표시하지 않는다 |
| A06 | 자료가 있는 개요에서 PDF 추가 | 기존 자료와 새 자료가 함께 남고 기존 채팅 기록도 유지된다 |
| A07 | 빈 개요·좁은 화면에서 업로드 | 파일 선택으로 추가할 수 있고 업로드 버튼과 결과를 확인할 수 있다 |
| A08 | 처리 중 이탈 후 재진입 | 서버 상태를 복원하고 분석 중 문서만 상태 확인을 재개한다 |
| A09 | 추가 자료 분석 완료 후 기존·새 채팅 진입 | 새 자료가 목록·검색 가능 범위에 반영되고 실제 질문에서 검색 대상이 된다 |
| A10 | 비 PDF·손상·크기 초과·통신 실패·분석 실패 | 유형에 맞는 오류와 재시도 방법을 제공하며 기존 자료를 보존한다 |
| A11 | 업로드·새 채팅 생성 연속 클릭 | 화면의 중복 요청을 막는다. 실패 후 재선택·재시도가 가능하다 |
| A12 | 채팅에서 개요 복귀 후 재진입 | 같은 탭의 미전송 질문·노트 초안이 유지되고 다른 채팅과 섞이지 않는다 |
| A13 | 답변 생성 중 화면 전환 | 중복 질문 없이 복귀 시 진행·완료 상태를 확인하고 다른 채팅에 답변이 섞이지 않는다 |
| A14 | 기존 기능 회귀 | PDF 페이지 인용·노트 인용·노트 초안 저장·퀴즈·오답노트 이동이 유지된다 |
| A15 | 같은 이름·복수 파일 입력 | 같은 이름은 기존 자료를 덮어쓰지 않고 복수 파일 입력은 명시적으로 안내한다 |

검증 시 프런트 빌드와 실제 API를 연결한 화면 흐름을 확인한다. 자료 공유 검증은 새 PDF에만 있는 내용으로 기존·새 채팅에서 질문하고 검색 근거에 포함되는지 확인한다. 경로 소속 검증과 상태 복원 등 실패 시 데이터가 섞일 수 있는 경계에는 필요한 자동 검증을 둔다. 목 화면만 확인한 결과를 실제 업로드·검색 성공으로 기록하지 않는다.

## 7. 제외와 완료 조건

이번 범위에서 워크스페이스·채팅 이름 변경·삭제, 자료 삭제·교체, 일괄 업로드, 중복 내용 탐지, OCR, 채팅별 독립 자료, 검색·생성 정책 변경은 추가하지 않는다. 기존 노트 연결·작성 기능은 개요와 채팅 사이에서 유지한다.

완료는 코드 구현, 인수 기준 검증, 관련 기획서·아키텍처와 실행 검증 기록 반영까지다. 현재는 PRD 작성만 완료했으며 구현·실행 검증은 수행하지 않았다.
