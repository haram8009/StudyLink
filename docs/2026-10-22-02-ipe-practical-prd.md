# StudyLink PRD — 정보처리기사 실기 대비 학습 에이전트로 전환

작성일: 2026-10-22 (Asia/Seoul)  
상태: 초안. 사용자와 설계 질의(grill)로 결정한 요구사항·인수 기준이다. 구현·실행 검증 전이다.  
기준: [용어집](../CONTEXT.md), [ADR 0003](adr/0003-ipe-practical-domain-and-sources.md), [구현기획서 v1.1](studylink-implementation-plan-v1.1.md), [아키텍처](studylink-architecture.md), [퀴즈 설정 PRD](quiz-customization-prd.md).

## 1. 문제와 목표

지금 시제품은 임의의 PDF 자료를 다루는 범용 학습 서비스다. 정보처리기사 실기 수험생에게는 세 가지가 부족하다.

- 교재를 올리기 전에는 개념 질문에 답할 근거가 없다.
- 수험서 PDF는 문제(앞)와 정답·해설(뒤)이 다른 페이지에 있어, "2025년 1회 1번 해설" 같은 질문을 임베딩 검색만으로는 잘 찾지 못한다.
- 실기는 용어·코드 결과를 직접 쓰는 시험인데 퀴즈는 4지선다뿐이다.

목표는 StudyLink 컨셉(워크스페이스·자료·노트 연결·근거 인용·오답→원문 복귀)을 유지하면서 위 세 가지를 1~2일, 3명으로 메우는 것이다. 차별점 두 가지(공간을 넘는 노트 연결, 오답에서 원문 복귀)는 새 도메인에서 그대로 보여준다.

## 2. 입력 자료

| 자료 | 사용 방식 |
| --- | --- |
| 출제기준↔위키 대응표 `backend/seed/ipe-2027-written-kowiki-match.csv` | 필기 출제기준 세세항목 174개, 위키 대응(직접 94·근사 44·없음 36), 실기 출제 수. 시드 입력과 출제 가중치에 쓴다. 출처·이용 조건은 `D:\SSAFY\streamlit_lab\docs\data\README.md` |
| 한국어 위키백과 문서 126개(직접·근사 대응 중복 제거, 약 1.7MB) | **개념 사전**으로 내장. 절 단위 스냅샷을 저장소에 둔다(CC BY-SA) |
| 길벗 실기 PDF 26개(`data/`, git 제외) | 내장하지 않는다. 학습자가 업로드한 **자료**로만 쓴다(ADR 0003). 데모는 2025년 1회 기출 PDF |

수험서 PDF 관찰(2026-10-22): PyMuPDF로 텍스트 추출이 된다(`sort=True`가 읽기 좋음). 회차별 기출은 "문제 N" 형식으로 앞쪽에 20문항, 뒤쪽에 정답·해설이 있다. 문제집은 "N." 문항마다 답과 `[ 해설 ]`이 붙는다. 그림·메모리 도식은 텍스트로 깨진다.

## 3. 범위

### 필수

| ID | 기능 | 완료 기준 |
| --- | --- | --- |
| I01 | 위키 시드 | 시드 스크립트가 대응표의 문서를 MediaWiki API로 받아 판 번호(oldid)를 고정하고 절 단위 JSON으로 저장한다. 각주·같이 보기·외부 링크 절은 뺀다. 결과는 저장소에 커밋한다 |
| I02 | 기본 워크스페이스 | 서버 시작 시 "정보처리기사 실기" 워크스페이스와 개념 사전 자료를 멱등하게 만들고 임베딩한다. 재시작해도 중복되지 않는다. 각 자료에 출제기준 항목 태그가 붙는다 |
| I03 | 텍스트 자료·절 인용 | 텍스트 자료는 절 단위로 청킹하고 인용 위치는 절 번호다. 답변·노트 인용·퀴즈 근거에서 "문서 제목 §절 제목"으로 보이고, 누르면 그 절을 펼친 텍스트 뷰어가 열린다. 뷰어에 원문 URL·판·라이선스를 표시한다 |
| I04 | 문항 라벨 | 업로드 PDF는 페이지 청킹을 유지하고, 정규식으로 "문제 N"/"N."·정답·해설 구간을 찾아 청크 앞에 `[파일명 · 문제 3 · 해설]` 형태의 라벨을 붙인다. 형식을 알아보지 못하면 라벨 없이 그대로 둔다 |
| I05 | 라벨 우선 검색 | 질문에 "(년도) (회차) (N번)" 패턴이 있으면 일치하는 라벨 청크를 근거에 먼저 넣고, 남은 자리는 기존 임베딩 검색으로 채운다 |
| I06 | 단답형 문항 | 퀴즈 설정에 형식(선다형/단답형)을 더한다. 단답형은 설명을 주고 용어를 쓰게 하며, 생성 때 허용 답안(한글·영문·약어)을 함께 만든다 |
| I07 | 단답형 채점 | 공백·대소문자·괄호를 정규화한 뒤 허용 답안과 일치하면 정답. LLM 채점은 하지 않는다. 오답노트에서 학습자가 "정답으로 처리"할 수 있고, 처리 여부와 시각을 기록한다 |
| I08 | 출제 가중치 | 기본 워크스페이스 퀴즈는 절을 고를 때 해당 출제기준 항목의 가중치 1+실기 출제 수(2021-1~2026-2)를 쓴다. 코드 분석 3항목(절차적·객체지향·스크립트 언어)은 위키 출제에서 뺀다. 코드 문제는 업로드한 문제집 PDF로 만든 퀴즈가 맡는다 |

### 스트레치

- "자주 나온 주제" 목록(출제기준 트리 + 출제 수)
- BM25 키워드 검색 결합
- 코드 실행 결과형 문항
- 문항 단위 파서(문제↔정답↔해설을 한 레코드로)

### 제외

수험서 PDF 내장·배포, LLM 서술형 채점·부분 점수, 위키 자동 갱신, 출제기준 원문 재배포, 로그인·공개 배포.

## 4. 데이터·계약 변경

- documents: `kind`(pdf/text, 기본 pdf), `source_url`, `revision`, `license` 추가. 텍스트 자료는 `page_count`에 절 수를 넣는다.
- document_sections(document_id, no, heading, text): 텍스트 자료의 절. `no`는 1부터.
- document_topics(document_id, 과목, 세세항목, 실기 출제 수): 출제기준 항목 태그. 한 문서가 여러 항목에 붙을 수 있다.
- 위치 번호: chunks·note_citations·questions의 `page`는 그대로 두고, 텍스트 자료에서는 절 번호로 해석한다. 인용 응답에 `kind`와 텍스트 자료의 `section_heading`을 더한다.
- questions: `type`(mcq/short, 기본 mcq), 단답형용 `accepted_answers_json`. 단답형의 `options_json`·`answer_option_id`는 비운다.
- attempts: 단답형 입력을 담는 `answer_text`. reviews: `overridden_at`("정답으로 처리" 시각).
- 텍스트 자료 본문 조회 API(절 목록·절 본문). 기존 `GET /api/documents/{id}/file`은 PDF 전용으로 남긴다.
- 퀴즈 생성 요청에 `format`(mcq/short) 추가. 문항 수·난이도·요청 개수 충족 규칙은 [퀴즈 설정 PRD](quiz-customization-prd.md)를 따른다. 제출은 단답형이면 `{question_id: answer_text}`.

세부 컬럼명·API 경로는 구현 시 아키텍처 문서에 확정해 적는다.

## 5. 데모 시나리오

1. 기본 "정보처리기사 실기" 워크스페이스에서 "세션 하이재킹이 뭐야?" → 위키 개념 사전의 절 인용이 붙은 답변 → 노트로 저장.
2. "내 기출" 워크스페이스를 만들고 2025년 1회 기출 PDF를 업로드, 1의 노트를 연결.
3. "2025년 1회 1번 해설 알려줘" → PDF 해설 페이지와 "내 노트"가 함께 인용된 답변. **(차별점 1)**
4. 기본 워크스페이스에서 단답형 퀴즈 → 오답에서 위키 절과 관련 노트로 이동. 표기만 다른 정답은 "정답으로 처리". **(차별점 2)**
5. Langfuse에서 3번 질문의 trace(라벨 우선 근거·프롬프트·토큰)를 보여준다.

## 6. 인수 기준

- 위 데모 1~5가 앱 재시작 후에도 끊김 없이 동작한다.
- 평가 질문 15개(위키 개념 질문 6, 2025년 1회 PDF 질문 4, 답 없음 5)에서 답 있음 10개 중 올바른 위치(절·페이지) 인용 8개 이상, 답 없음 5개 중 보류 4개 이상. 기존 평가 스크립트(`backend/eval/run_eval.py`)로 CSV를 만들고 사람이 판정한다. 수험서 질문은 로컬에서만 재현된다.
- "N회 N번" 질문 4개는 모두 해당 문항 라벨 청크가 근거에 들어간다.
- 단답형 10문항을 사람이 검토해 정답·허용 답안이 틀린 문항이 1개 이하, 허용 답안 누락으로 맞는 답이 오답 처리되는 문항이 2개 이하.
- 저장소에 수험서 PDF·문제 원문이 없고, 위키 스냅샷에 문서별 URL·판 번호·라이선스가 있다.
