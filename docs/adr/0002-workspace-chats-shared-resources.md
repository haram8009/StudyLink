# 워크스페이스의 자원은 공유하고 채팅의 대화 문맥은 분리한다

## Context

사용자가 워크스페이스 안에서 여러 채팅을 만들고, 모든 채팅에서 같은 노트·업로드 PDF를 열람하기를 명시했다. 같은 채팅에서 이전 질문·답변을 이어 묻는 방식도 확인했다. 기존 워크스페이스 단위 질문·최근 답변 설계만으로는 주제별 대화 기록과 문맥을 구분할 수 없다.

## Decision

- 워크스페이스는 여러 채팅과 자료를 소유한다. 노트 원본은 기존처럼 독립적이며 워크스페이스와 연결된다. 채팅별 자료 복사나 별도 노트 연결을 만들지 않는다.
- 채팅은 질문·답변 기록을 가지며 후속 질문의 문맥은 해당 채팅에서만 가져온다. 다른 채팅의 기록은 자동 검색·참조하지 않는다.
- 이전 대화는 질문의 의미를 해석하는 입력이다. 답변의 사실 근거는 매 요청 현재 워크스페이스의 자료·연결 노트에서 검색하고, 그 요청에서 제공한 근거 ID만 인용한다.
- 기존 답변을 삭제하지 않고 워크스페이스별 이전 대화로 이관한다. 새 채팅에 이전 기록을 복제하지 않는다. 초기화·재시작 시 이관을 반복해도 중복되지 않아야 한다.

## Considered Options

- 워크스페이스에 질문 기록 하나만 유지: 구현은 단순하지만 서로 다른 학습 주제를 분리할 수 없다.
- 채팅마다 자료 복사: 대화 격리는 쉬우나 중복 업로드·수정 불일치가 생기고 공통 자원 요구를 충족하지 못한다.
- 워크스페이스의 모든 대화 문맥 공유: 같은 자료를 활용하는 것과 같은 대화를 이어가는 것을 혼동해 다른 채팅의 주제가 섞인다.

## Consequences

채팅 테이블과 답변의 채팅 참조, 채팅 목록·생성·기록·질문 API가 필요하다. 화면에는 채팅 선택과 공통 자원 열람을 함께 제공한다. 문맥 입력에는 길이 상한을 두며, 재시작 후 기록 보존과 채팅 간 문맥 격리를 검증한다. 채팅 이름 변경·삭제·장기 문맥 요약은 이번 핵심 범위에 추가하지 않는다.
