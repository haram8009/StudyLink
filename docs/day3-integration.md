## 작업 방식

사용자 지시로 담당 에이전트 5개(B 백엔드, C1 퀴즈 생성, C2 노트 초안·관련 노트, C3 평가, A 프런트)를 같은 작업 디렉터리에서 파일 소유 범위를 나눠 동시에 실행했다. 시작 전 통합 담당이 GMS 어댑터에 `register_mock(schema_name, build)` 훅을 추가해, 퀴즈·초안 모듈이 어댑터를 고치지 않고 각자 목 응답을 등록하게 했다. 담당 간 함수 계약(생성 결과 형식·예외 클래스·초안 인용 형식)은 시작 시 고정했다. git commit은 하지 않았다.

## 평가 결과 (자동 비교, 사람 판정 아님)

| 설정 | 답 있음(목표 8/10) | 답 없음 보류(목표 4/5) | 데모 4단계 노트 인용 |
| --- | --- | --- | --- |
| 기본 MIN_SCORE 0.2, RELATIVE_MARGIN 0.1 | 8/10 | 2/5 | 안 됨 |
| RELATIVE_MARGIN 0.15 | 10/10 | 2/5 | 안 됨 |
| answer-v3 + RELATIVE_MARGIN 0.15 | 10/10 | 4/5 (U05는 공급자 오류, 재실행 시 보류 → 판정 기준 5/5) | 안 됨 |
| answer-v4 + link_notes + 데모 4단계 질문 변경 (현재 기본) | 10/10 | 5/5 | 됨 (단독 5/5회, 전체 실행에서도 Y) |

- RELATIVE_MARGIN 0.15 권장(평가 담당). 노트 점수가 자료보다 높을 때 자료 페이지가 근거에서 빠지는 문제를 막는다. 설정 기본값은 아직 바꾸지 않았다.
- 답 없음 질문은 "직접적인 언급은 없으나…"로 주변 근거를 붙여 grounded가 되며, 검색 점수가 정상 질문보다 높아 기준값으로 분리되지 않는다. 답변 프롬프트 문제다.
- 데모 4단계 노트는 4회 모두 근거 2위로 들어갔으나 인용되지 않았다. 기준값으로 해결되지 않는다.
- 상세 수치·실패 질문·trace ID는 [평가 기록](day3-eval.md).
