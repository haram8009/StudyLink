# 3일차 평가 기록 — 검색 품질 질문셋·도구·기준값 비교

작성일: 2026-10-22 (Asia/Seoul). 담당 C3(평가).
기준: [3일차 PRD](studylink-day3-prd.md) "평가"·인수 시나리오 9, [구현기획서 v1.1](studylink-implementation-plan-v1.1.md) 11절, [2일차 PRD](studylink-day2-prd.md) "검색 품질 보정".

상태: 평가 도구와 질문셋을 만들고 목 모드·실제 GMS로 실행했다. **아래 수치는 모두 자동 비교이며 사람 판정이 아니다.** 근거가 주장을 실제로 뒷받침하는지는 CSV의 `human_*` 칸에 사람이 적어야 하고, 인수 시나리오 9(사람 판정 8/10·4/5)는 아직 완료가 아니다. 설정 기본값(`config.py`, `.env.example`)은 바꾸지 않았다.

## 도구 동작

- 실행마다 새 DATA_DIR에서 `init_db` → 워크스페이스 2개 생성 → `upload_document` + `ingest_document`로 PDF 수집 → `create_note`로 노트 저장·두 워크스페이스 연결(저장 시 색인) → 질문마다 `answer_question(workspace_id, question)`(history 없음, include_notes 기본 true). 앱 코드는 import만 한다.
- 저장된 답변 body에서 근거 수·점수(`retrieval`)·`note_guaranteed`·`research`·`search_query`·`trace_id`를 읽는다. 질문을 한 번 더 임베딩해 MIN_SCORE 필터 없는 원 점수(최고 자료·노트 점수, 기대 페이지 순위·점수)도 남긴다. 기준값 후보를 실행 없이 비교하는 데 쓴다.
- 자동 비교: 답 있음은 grounded이고 기대 자료·페이지 인용이 하나라도 있으면 `auto_expected_page_cited=Y`. A06은 `auto_note_cited`를 따로 표시. 답 없음은 status가 insufficient_evidence면 `auto_withheld=Y`. 예외는 `error:<type>`으로 기록하고 계속한다.
- CSV(utf-8-sig) 열: 질문 정보, status, 근거 수(자료/노트), 근거 점수 목록, 최대·최소 점수, 노트 보장, 재검색 여부·질의, search_query, 인용 자료/페이지·노트, 자동 비교 3종, 원 점수 4종, trace_id, 소요 시간, 답변 본문, `human_verdict`·`human_supported`·`human_comment`(빈 칸).

### 실패 질문 분석

- A01(실제 1): 노트 점수 0.512가 자료 p.3 0.491보다 높아 근거가 [노트, p.3] 둘이었고 답변이 노트만 인용했다. REL 0.15·0.05 실행에서는 p.3과 노트를 함께 인용해 통과.
- A02(실제 1·3): 노트 0.631, 자료 p.3 0.511. 차이 0.12가 REL 0.1·0.05보다 커서 근거가 노트 하나뿐이었고, 노트에는 forget gate 설명이 없어 보류됐다. REL 0.15에서는 p.3이 들어와 통과. 같은 개념의 노트가 자료보다 점수가 높으면 상대 기준이 자료를 밀어내는 사례다.
- A07(실제 3): 근거 4개(REL 0.05) 중 p.4가 빠져 p.9를 인용. 기대 페이지 원 점수 0.253으로 5위라 좁은 상대 기준에서 빠진다.
- U01·U03·U04(모든 실제 실행): 답변이 "직접적인 언급은 없으나…"로 시작하거나 주변 근거를 붙여 grounded로 끝났다. U04는 LoRA를 자료의 fine-tuning 문장(p.4)으로 설명하고 실제 3에서는 자료에 없는 "저차원 행렬 분해"를 [e1]에 붙였다. U03은 실제 3에서 "입력 토큰에 positional encoding이 더해진다 [e2]"처럼 텍스트에 없는 그림 내용을 인용 근거로 붙였다. 사람 판정에서 근거 미지지로 처리될 대상이다.
- 이 셋의 최고 근거 점수(0.348~0.470)는 통과한 답 있음 질문의 최고 점수(A10 0.318, A07 0.320, A06 0.335, A03 0.356)보다 높다. **MIN_SCORE로는 분리할 수 없고**, 보류 실패는 생성 단계(근거가 질문을 직접 답하지 않을 때 segments를 비우는 규칙)의 문제다.

### 노트 인용 확인 (데모 4단계)

- 네 번의 실제 실행 모두 A06에서 노트가 근거에 들어갔지만(노트 원 점수 0.286, 근거 목록 2번째) 답변은 Transformer p.3만 인용했다. 실제 3에서는 근거가 [p.3, 노트] 둘뿐이었는데도 인용하지 않았다.
- 실제 4에서 노트에 "층이 깊은 신경망에서도 역전파 때 앞쪽 층으로 갈수록 기울기가 작아져 학습이 어려워진다"는 학습자 메모를 덧붙여도 인용되지 않았다(노트 최고 점수 0.286 그대로).
- 결론: 기준값으로는 노트 인용을 만들 수 없다. 검색·노트 보장은 동작하고, 생성 모델이 직접 답이 되는 자료 근거만 고른다. 데모 4단계를 보장하려면 답변 프롬프트(예: 연결 노트가 질문 개념과 관련되면 함께 인용) 또는 노트 본문을 바꿔야 하며, 이는 답변 그래프 담당의 결정 사항이다. 데모 노트 본문을 바꾸는 방식은 과적합 우려가 있다.
- A06 trace ID: 실제 1 `ea10ddd31dacb5dcf83d23c8dea08680`, 실제 2 `63a6654621dff22733f64ecef902e25d`, 실제 3 `a447fa33622b29749584aab4aed5444f`, 실제 4 `4cb5220e17f89429e69dd48aca7b45bb`. 나머지 질문의 trace ID는 각 실행의 `results.csv`에 있다. 원격 Langfuse에서 trace를 다시 열어보지는 않았다.

## 권장 기준값

- **MIN_SCORE 0.2 유지.** 원 점수상 A06의 노트(0.286)를 살리려면 0.28 이하여야 하고, 답 있음 최고 자료 점수의 최저는 0.318(A10)이다. 보류 실패 질문은 0.348 이상이라 0.2~0.28 사이에서는 자동 결과가 달라지지 않는다(U05는 0.264로 이미 생성 단계에서 보류). 0.3 이상은 노트 인용 자체를 막는다(원 점수 기반 추정, 실행하지 않음).
- **RELATIVE_MARGIN 0.15 권장(현재 기본 0.1).** 근거: 같은 개념의 노트가 자료보다 0.1 넘게 높을 때(A02) 자료 페이지가 빠지는 문제를 막았고, 실제 2에서 답 있음 10/10(자동). 대가로 근거 수가 늘었다(A09 4→12개, 15문항 총 67.8초→76.0초). 답 없음 보류는 0.05·0.1·0.15 모두 2/5로 상대 기준의 영향이 없었다.
- 기본값 변경 여부는 사람 판정 후 답변 그래프·설정 담당이 결정한다. 이번 작업에서는 설정 기본값을 바꾸지 않았다.

## 2026-10-22 재측정: answer-v3·RELATIVE_MARGIN 0.15

통합 담당이 위 결과를 바탕으로 답변 생성을 바꾸고 같은 도구로 다시 쟀다.

- 변경: 답변 출력 스키마에 `answerable`(segments보다 먼저)을 추가하고, false면 segments가 있어도 보류한다(재생성 없음). 프롬프트 `answer-v3`: 질문의 핵심 답이 근거 텍스트에 직접 있을 때만 answerable, 그림·표에만 있거나 추론·일반 지식이 필요하면 보류, "직접적인 언급은 없으나" 같은 덧붙임 금지, 노트가 질문 개념의 배경·원인·관련 문제를 설명하면 연결 문장으로 인용. `RELATIVE_MARGIN` 기본값 0.15로 변경(config·.env.example·평가 도구 기본값).
- 실행 `real-answer-v3-rm0.15`(MIN 0.2, REL 0.15, 실제 GMS): 답 있음 **10/10**, 답 없음 보류 **4/4 + U05 공급자 오류**. U05는 GMS 응답 지연으로 ProviderUnavailable(같은 실행의 여러 호출이 17~21초)이며, `real-answer-v3-rm0.15-retry`에서 단독 재실행해 보류됐다. 따라서 생성 판정 기준으로는 5/5, 한 번의 실행 기준으로는 4/5다.
