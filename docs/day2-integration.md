# 2일차 구현·통합 기록 — 여러 채팅과 공통 자원

작성일: 2026-10-21 (Asia/Seoul)
상태: 워크스페이스 안 여러 채팅과 공통 자원(PDF·연결 노트) 열람·검색을 구현하고 통합 확인했다. 2일차 PRD 전체 완료는 아니다(아래 "남은 일").
기준: [ADR 0002](adr/0002-workspace-chats-shared-resources.md), [2일차 PRD](studylink-day2-prd.md). 담당별 기록: [백엔드](day2-backend.md), [에이전트](day2-agent.md), [프런트](day2-frontend.md).

## 작업 방식

사용자 지시로 프런트(A)·백엔드(B)·에이전트(C) 담당 에이전트 3개가 같은 작업 디렉터리에서 파일 소유 범위를 나눠 병렬 구현했다. 통합 담당이 계약 불일치 수정·전체 검증·문서 동기화를 맡았다. git commit·push는 하지 않았다.

## 구현 범위

- B: chats 테이블, answers.chat_id와 기존 답변의 "이전 대화" 채팅 이관(멱등), 채팅 목록·생성·조회·messages·ask, 같은 채팅 동시 요청 409, 채팅별 문맥(최근 6쌍·12,000자), 노트 생성·조회·수정·연결·해제, 워크스페이스 상세의 notes·chats, 답변 복구 API.
- C: 후속 질문 재작성(query-followup-v1), 약한 근거 재검색 1회(query-research-v1), 답변 프롬프트 answer-v2, 연결·색인 성공 노트 검색과 노트 최소 1개 보장, `index_note`.
- A: 채팅 목록·전환, 채팅별 요청 상태, 공통 자원 패널(자료·연결 노트·노트 작성), 인용 클릭 시 PDF 페이지·노트 미리보기, 마지막 채팅 복원, 목 모드 확장.
- 통합 수정: 노트 인용 표시가 백엔드 응답의 `id` 대신 `citation_id`를 읽던 불일치를 프런트에서 둘 다 받도록 고쳤다.

모두 소수 smoke 결과이며 검색 품질 평가가 아니다. 문맥 격리의 증거는 기록·문맥 입력 분리다. 데모 PDF가 작아 채팅 B에서 문맥 없이 같은 후속 문장을 물어도 LSTM을 답했으므로, 답변 내용만으로 문맥 효과를 판정할 수는 없다. 원격 Langfuse trace 재조회는 이번에 하지 않았다.

검증은 운영 중인 8000/5173 서버와 실제 `backend/data`를 건드리지 않도록 DB 사본과 별도 포트(8010/5181)에서 수행했다. 실행 중인 8000번 서버는 1일차 코드이므로 2일차 기능을 쓰려면 재시작해야 한다. 재시작하면 `backend/data/app.db`에 이관이 적용된다.
